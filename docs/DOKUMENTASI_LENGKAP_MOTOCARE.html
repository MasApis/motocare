BAB 1: PENDAHULUAN & RINGKASAN PROYEK

1.1 Latar Belakang

Sepeda motor jenis transmisi otomatis (matic) merupakan moda transportasi harian paling dominan di Indonesia bagi kalangan pelajar, mahasiswa, pekerja komuter, hingga pengemudi transportasi daring. Kendati demikian, tingkat kelalaian pemilik dalam melakukan pemeliharaan berkala masih sangat tinggi. Pemilik motor matic seringkali terlambat mengganti oli mesin, mengabaikan oli transmisi/gardan, atau membiarkan sabuk CVT (V-Belt) melampaui batas keausan hingga putus mendadak di jalan raya.

Permasalahan utama yang sering terjadi pada pengguna adalah:

  1. Tiap suku cadang memiliki interval kilometer yang berlainan (oli mesin tiap 2.000 km, oli gardan tiap 8.000 km, dan V-belt tiap 20.000 km), sehingga sulit diingat tanpa alat bantu.
  2. Buku servis manual rentan hilang, kotor, atau tertinggal di rumah saat pengguna berada di bengkel.
  3. Ketidaktahuan pemilik motor dalam mendiagnosa gejala kerusakan dini (seperti bunyi gregel di CVT atau penurunan akselerasi).
  4. Tidak tersedianya rekapitulasi pengeluaran servis bulanan untuk memonitor anggaran kendaraan.

Untuk mengatasi masalah tersebut, dikembangkanlah MotoCare, sebuah aplikasi mobile Android berbasis Flutter yang menggabungkan kalkulasi matematis usia pakai suku cadang, sistem notifikasi lokal otomatis, dan asisten cerdas berbasis kecerdasan buatan (MotoAI) untuk membantu pemilik motor matic merawat kendaraannya secara presisi, terstruktur, dan mandiri.

1.2 Tujuan Proyek

  • Membantu pemilik motor matic mengetahui sisa kilometer dan waktu aman servis tanpa perlu menghafal angka odometer.
  • Menyediakan linimasa riwayat servis bengkel yang mendetail (mencatat multi-item komponen, aksi diganti atau dibersihkan, hingga suku cadang tambahan).
  • Menghadirkan fitur pengingat proaktif sebelum komponen aus memasuki zona merah batas kritis (< 10%).
  • Menyediakan asisten virtual konsultasi mekanik matic (MotoAI) yang dapat mendiagnosa keluhan motor secara cepat dan gratis.
  • Membuat laporan pengeluaran bulanan formal berformat PDF yang dapat langsung dicetak atau dibagikan.

1.3 Target Pengguna

Pengguna utama MotoCare adalah pemilik sepeda motor matic harian di Indonesia, mencakup mahasiswa, pekerja komuter, dan mitra pengemudi ojek online yang membutuhkan pemantauan performa kendaraan yang andal dan hemat biaya.

3.2 Aturan Keamanan (Security Rules)

Keamanan Firestore diamankan dengan prinsip hak akses terkunci (Owner-Only Access). Pengguna hanya diizinkan membaca, menambah, mengubah, dan menghapus dokumen miliknya sendiri berdasarkan token request.auth.uid.

rules_version = '2';
service cloud.firestore {
  match /databases/{database}/documents {
    match /users/{userId}/{document=**} {
      allow read, write: if request.auth != null && request.auth.uid == userId;
    }
  }
}

3.3 Fitur Offline Persistence

Cloud Firestore pada MotoCare dikonfigurasi dengan cache offline aktif secara default. Pengguna dapat membuka dashboard, melihat status kesehatan motor, memperbarui KM, serta mencatat servis ketika berada di ruang bawah tanah (basement) atau daerah tanpa sinyal internet. Seluruh perubahan akan otomatis disinkronkan ke cloud begitu koneksi internet pulih.

Seluruh aturan matematika dan validasi diletakkan di dalam fungsi murni di folder lib/core/, terbebas dari ketergantungan antarmuka grafis atau Firebase SDK. Pendekatan ini memungkinkan pengujian unit (unit testing) dapat dijalankan dengan kepastian 100%.

4.1 Komponen & Interval Default

Komponen Tipe Internal Interval Default Aksi yang Didukung Penjelasan Fungsi
Oli Mesin engine_oil 2.000 km Diganti (Replaced) Melumasi ruang bakar dan piston mesin matic. Kritis terhadap overheat.
Oli Gardan gear_oil 8.000 km Diganti (Replaced) Melumasi gigi transmisi roda belakang matic. Rasio penggantian 2:1 atau 3:1 oli mesin.
V-Belt & CVT v_belt 20.000 km Diganti atau Dibersihkan Sabuk karet penggerak pulley CVT. Wajib dicek/dibersihkan berkala dan diganti saat aus.

4.2 Rumus Perhitungan Persentase Sisa Usia Pakai

Perhitungan persentase kesehatan komponen dihitung menggunakan rumus matematis:

km_terpakai = km_sekarang - km_servis_terakhir
sisa_km     = interval - km_terpakai
persentase  = clamp(sisa_km / interval, 0.0, 1.0) * 100%

Jika odometer motor telah melampaui batas interval (misal pemakaian 2.300 km pada oli mesin dengan interval 2.000 km), nilai sisa_km akan bernilai negatif (-300 km), persentase dikunci pada angka 0%, dan status kartu menampilkan teks peringatan "Lewat 300 km".

4.3 Ambang Batas Status & Warna Indikator

Status komponen tidak hanya bergantung pada warna (demi memenuhi standar aksesibilitas), melainkan dilengkapi label teks eksplisit:

Rentang Persentase Label Status Kode Warna Arti & Tindakan
> 30% Aman Hijau (#16a34a) Kondisi suku cadang masih sangat prima. Belum memerlukan tindakan bengkel.
10% s.d. 30% Peringatan Kuning / Amber (#d97706) Komponen mulai aus. Pengguna disarankan menyiapkan dana dan menjadwalkan servis.
< 10% atau Lewat KM Batas Habis Merah (#dc2626) Kondisi kritis / zona merah. Wajib segera diganti agar tidak merusak mesin.

4.4 Perhitungan Rata-rata Jarak Tempuh Harian (KM/Hari)

Untuk memprediksi kapan motor akan kehabisan sisa usia pakai komponen, aplikasi menghitung rata-rata harian dengan aturan:

  1. Mengambil catatan odometer dalam 30 hari terakhir.
  2. Mencari selisih jarak: km_terbaru - km_tertua.
  3. Mencari selisih waktu: tanggal_terbaru - tanggal_tertua (dalam satuan hari).
  4. Syarat Validitas: Dibutuhkan minimal 2 catatan log odometer dengan selisih waktu minimal ≥ 3 hari.
  5. Fallback Default: Jika data kurang (misal motor baru didaftarkan), sistem secara cerdas menggunakan estimasi awal 20 km/hari (ditampilkan dengan tanda ± 20 km/hari).

4.5 Rumus Estimasi Tanggal Masuk Zona Merah (Push Notification Trigger)

Tanggal di mana komponen memasuki zona merah (ambang sisa 10%) dihitung secara deterministik:

km_batas_merah = 0.10 * interval
km_menuju_merah = sisa_km - km_batas_merah
hari_menuju_merah = max(0, ceil(km_menuju_merah / rata2_km_harian))
tanggal_target   = tanggal_hari_ini + hari_menuju_merah

Notifikasi dijadwalkan otomatis berdering pada tanggal_target tepat pukul 08:00 pagi waktu lokal.

4.6 Aturan Bisnis Servis Multi-Item (F5 Revisi) & Rollback Otomatis

Satu kali kunjungan servis ke bengkel dapat mencakup banyak item sekaligus dengan aturan reset sebagai berikut:

  • Item Komponen Diganti: Mereset nilai lastServiceKm komponen bersangkutan ke KM saat servis, sehingga kartu kesehatannya kembali 100%.
  • Item Komponen Dibersihkan (Khusus V-Belt): Hanya dicatat di linimasa riwayat servis, tidak mereset kartu kesehatan V-belt.
  • Item Part Lain: (misal Roller, Kampas Rem, Busi, Filter Udara) disimpan di riwayat pengeluaran dan tidak memengaruhi ketiga kartu utama.
  • Penghapusan Catatan Servis (Rollback): Jika pengguna menghapus riwayat servis, sistem secara otomatis menghitung ulang lastServiceKm berdasarkan catatan servis penggantian sebelumnya. Jika tidak ada catatan lain, nilai komponen dikembalikan ke baselineKm saat motor pertama kali dibuat.

F1. Autentikasi Pengguna (Firebase Auth)

  • Pendaftaran akun baru dengan validasi format email dan kata sandi minimal 6 karakter.
  • Penanganan pesan error ramah dalam Bahasa Indonesia (misal: "Email ini sudah terdaftar", "Kata sandi salah").
  • Status login persisten (Auto-login saat aplikasi ditutup dan dibuka kembali).
  • Fitur keluar akun (Logout) dengan tombol aman pada dashboard.

F2. Manajemen Multi-Kendaraan & Carousel

  • Pengguna dapat mendaftarkan lebih dari satu motor matic dalam satu akun.
  • Pilihan preset motor populer: Beat, Vario 125/160, Scoopy, PCX, NMAX, Aerox, Mio M3, Fazzio, Lexi, dll., serta opsi input tipe kustom.
  • Komponen langsung diinisialisasi otomatis saat motor dibuat dengan interval standar pabrikan.
  • Pengaturan interval KM per komponen dapat dikustomisasi per motor sesuai rekomendasi buku manual.
  • Tampilan kartu carousel interaktif yang dapat digeser kiri/kanan di bagian atas dashboard.

F3. Dashboard Motor Health Card

  • Menampilkan 3 kartu visual: Oli Mesin, Oli Gardan, dan V-Belt.
  • Progress bar proporsional yang berubah warna secara dinamis (Hijau, Kuning, Merah).
  • Menampilkan sisa kilometer dan teks status (Aman, Peringatan, Batas Habis, Lewat X km).
  • Kartu interaktif: Mengetuk kartu langsung membuka formulir servis dengan komponen tersebut telah terpilih otomatis.

F4. Odometer Hibrida & Log Jarak Tempuh

  • Tombol Update KM cepat pada dashboard.
  • Validasi ketat: Angka KM baru tidak boleh lebih kecil dari KM saat ini (KM tidak boleh mundur).
  • Input non-angka ditolak dengan pesan error yang jelas.
  • Setiap pembaruan KM otomatis memperbarui persentase kesehatan dan menghitung ulang estimasi rata-rata km/hari.

F5. Pencatatan Servis Multi-Item & Linimasa Riwayat

  • Formulir komprehensif: Odometer servis, tanggal pengerjaan, nama bengkel/lokasi, total biaya, dan catatan opsional.
  • Dukungan multi-item: Memilih satu atau beberapa komponen (oli mesin, oli gardan, V-belt) dengan aksi Diganti atau Dibersihkan.
  • Penambahan baris suku cadang lain (nama part wajib, merek opsional) secara dinamis.
  • Format mata uang Rupiah standar Indonesia (Rp 145.000) dan format tanggal lokal id_ID.
  • Fitur hapus catatan servis dengan dialog konfirmasi demi mencegah ketidaksengajaan.

F6. Smart Push Notification (Lokal)

  • Menggunakan flutter_local_notifications dengan penjadwalan alarm persis (Exact Alarm).
  • Notifikasi otomatis dijadwalkan ulang setiap kali ada pembaruan odometer atau pencatatan servis baru.
  • Notifikasi muncul pukul 08:00 pagi waktu lokal pada tanggal estimasi zona merah.
  • Penanganan izin notifikasi yang ramah pengguna (banner panduan jika izin belum diaktifkan).

F7. Chatbot Diagnosa Asisten Motor "MotoAI"

  • Asisten berbasis LLM (Groq Cloud API) dengan persona ahli mekanik motor matic berpengalaman.
  • Otomatis menyertakan konteks motor yang sedang aktif (tipe motor, KM terkini, status oli dan CVT) ke dalam prompt sistem.
  • Dilengkapi disclaimer keselamatan berkendara di setiap jawaban.
  • Penolakan sopan untuk pertanyaan di luar topik otomotif/sepeda motor.
  • Antarmuka percakapan interaktif (chat bubble, status indikator mengetik, batas input 300 karakter demi penghematan kuota).

F8. Laporan Pengeluaran Bulanan & Cetak PDF

  • Menampilkan ringkasan total biaya pengeluaran servis pada bulan terpilih.
  • Navigasi chevron untuk berpindah bulan dan tahun secara leluasa.
  • Tombol Unduh Laporan PDF yang memproduksi dokumen PDF resmi dengan layout tabel profesional (tanggal, ringkasan pekerjaan, bengkel, biaya, dan total).
  • Dukungan pratinjau langsung, integrasi pencetakan sistem Android, dan pembagian berkas (share) ke WhatsApp/Email.

BAB 8: PANDUAN INSTALASI, KONFIGURASI, & PUBLIKASI

8.1 Prasyarat Sistem

  • Flutter SDK versi 3.13.5 atau lebih baru.
  • Java Development Kit (JDK 17 atau 21).
  • Android Studio / Android SDK (Command-line Tools, Platform-Tools).
  • Ponsel Android fisik dengan fitur USB Debugging aktif, atau Android Emulator.

8.2 Langkah Instalasi & Menjalankan Proyek

# 1. Kloning repositori kode
git clone https://github.com/USERNAME/motocare.git
cd motocare

# 2. Ambil seluruh pustaka dependensi
flutter pub get

# 3. Jalankan aplikasi dalam mode debug di HP Android
flutter run

8.3 Konfigurasi Backend Firebase (Spark Tier Gratis)

  1. Buat proyek baru di Firebase Console dengan paket gratis Spark.
  2. Aktifkan Email/Password pada tab Authentication.
  3. Buat database Cloud Firestore dan terapkan Security Rules sesuai Bab 3.2.
  4. Unduh berkas google-services.json dan simpan di android/app/google-services.json.
  5. Generate berkas opsi FlutterFire: flutterfire configure.

8.4 Konfigurasi Kunci Asisten AI (MotoAI)

Kunci API Groq tidak pernah disimpan di dalam repositori kode demi keamanan. Kunci dapat diinjeksi saat build/run:

flutter run --dart-define=GROQ_API_KEY="gsk_kunci_groq_anda_disini"

8.5 Panduan Build & Publikasi APK Release ke GitHub

  1. Pastikan berkas keystore rilis telah dibuat pada android/app/upload-keystore.jks.
  2. Buat berkas konfigurasi android/key.properties: 
    storePassword=password_keystore_anda
keyPassword=password_key_anda
keyAlias=upload
storeFile=upload-keystore.jks
  3. Jalankan proses kompilasi rilis: 
    flutter build apk --release
  4. Berkas APK yang dihasilkan berada di build/app/outputs/flutter-apk/app-release.apk (ukuran sekitar 60 MB).
  5. Buka menu Releases → Draft a new release di repositori GitHub Anda, unggah berkas APK tersebut, buat tag v1.0.0, dan klik Publish release.
